# Касимовские Зори — перенос контента со старого сайта на WordPress

## Контекст

Санаторий «Касимовские Зори». Старый сайт: https://kasimovskie-zori.ru/ — статичные .html-страницы, самописный (не WordPress и не Bitrix), админки и выгрузки нет.
Новый сайт: WordPress, своя тема по прототипу (структура блоков ниже).

Цель проекта: вытащить весь контент старого сайта (тексты, фото, документы), переписать под блоки прототипа, согласовать с руководством санатория, залить в WordPress.

Разделение работы:
- **Claude Code (здесь)** — механика: скачивание, разбор, инвентаризация, фото, затем JSON, импортёр, проверка.
- **Claude в чате (проект «зори» на claude.ai)** — переписывание текстов и документ на согласование. Здесь тексты НЕ переписываем.

## Правила (соблюдать всегда)

1. **Экономь контекст.** Не читай сырые HTML и большие файлы целиком. Пиши скрипты (Python 3 + BeautifulSoup/lxml), запускай, смотри на итоговые цифры и 1–2 примера.
2. **Фото не открывай по одному** — смотри только листы-превью (contact sheets).
3. **Тексты извлекай дословно.** Не переписывай, не сокращай, не «улучшай», не додумывай недостающее (цены, ФИО, названия, цифры). Где на старом сайте пусто — ставь `[НЕТ НА СТАРОМ САЙТЕ]`.
4. **Оригиналы не трогай.** `raw/` — только чтение. Всё обрабатывай в копиях.
5. **Качай вежливо:** только домен kasimovskie-zori.ru, пауза ~1 с между запросами, один поток.
6. **Боевой WordPress — только после моего явного «да»** в текущем разговоре. Сначала локальная или тестовая установка, dry-run, бэкап БД.
7. **Веди PROGRESS.md:** после каждого этапа — что сделано, где результаты, что осталось, открытые вопросы. Новая сессия начинается с чтения CLAUDE.md и PROGRESS.md, а не с повторного анализа.
8. **Останавливайся в конце каждого этапа** с коротким итогом (цифры + пути к файлам). К следующему этапу сам не переходи.

## Структура папки

```
CLAUDE.md            этот бриф
PROGRESS.md          журнал этапов
raw/site/            зеркало старого сайта (только чтение)
raw/ftp-images/      оригиналы картинок с хостинга, если появятся (только чтение)
theme/               тема WordPress, если положу (только чтение на этапах 1–4)
scripts/             все скрипты
inventory/           pages.csv, images.csv, facts.csv, content-map.csv, redirects.csv, qa-report.md
content/old/         извлечённые тексты, по файлу на страницу (.md)
content/approved/    утверждённые тексты (экспорт из документа согласования)
content/json/        данные для импорта
media/originals/     копии картинок без изменений
media/renamed/       переименованные копии по разделам
media/sheets/        листы-превью
handoff/             пакет для передачи в чат
importer/            плагин-импортёр / WP-CLI команда
```

## Этапы

### Этап 1. Скачивание
- Проверь robots.txt и sitemap.xml.
- Зеркало сайта через wget в `raw/site/`: рекурсивно, с page-requisites, только этот домен, пауза между запросами, **без конвертации ссылок** (нужны исходные URL).
- Найди картинки в CSS, inline-style и JS, которые wget не взял, — докачай.
- Скачай документы (PDF, DOC, XLS: лицензии, прайсы, договоры, правила).
- Внешние встраивания (виртуальный тур, карты, видео, виджеты бронирования) не качай — запиши URL.
- Результат: `inventory/pages.csv` — url, HTTP-статус, title, h1, meta description, число слов, число картинок, внешние встраивания.

### Этап 2. Тексты
- `scripts/extract.py`: для каждой страницы выдели основной контент. Шапку, меню, подвал и другие блоки, общие для всех страниц, вынеси один раз в `content/old/_common.md` (контакты, адрес, реквизиты, часы работы).
- Разбей по заголовкам и якорям, сохрани порядок. Таблицы → markdown-таблицы, списки → списки.
- Файл на страницу `content/old/<slug>.md`: front matter (old_url, title, meta description, h1), затем секции `## Заголовок {#якорь}` с текстом дословно, под каждой секцией — список её картинок (новое имя файла, исходный URL, alt).
- Все цены, телефоны, e-mail, адреса, часы, цифры (номера, гектары, корпуса) — в `inventory/facts.csv` (что, значение, страница, якорь).
- Проверка полноты: число слов в .md против числа слов на страницах (без общих блоков). Расхождение больше 5% — покажи, где.

### Этап 3. Фото
- Скопируй в `media/originals/`, сохранив пути.
- `inventory/images.csv`: исходный URL, локальный путь, на каких страницах и в каких секциях используется, alt/title со страницы, ширина×высота, вес, формат, sha1, группа дублей.
- Дубли и почти-дубли (одинаковый хэш или perceptual hash — разные размеры одного фото) сгруппируй, основной оставь самую крупную версию.
- Пометки: `low_res` — меньше 1200 px по длинной стороне; `icon` — иконки и декор (меньше 200 px, svg, png-пиктограммы).
- Переименованные копии: `media/renamed/<раздел>/<раздел>-<nn>.jpg`, латиницей. Раздел — slug новой страницы или блока по карте контента; если неясно — по старой странице.
- Листы-превью `media/sheets/<раздел>.jpg`: сетка миниатюр, под каждой — новое имя файла и размер.
- Если есть `raw/ftp-images/` — сопоставь по имени и хэшу и бери оттуда более крупные версии.

### Этап 4. Карта контента, модель данных, пакет для чата
- `inventory/content-map.csv`: старый URL#якорь → новая страница → блок прототипа → тип (страница / процедура / программа / проживание / акция / FAQ / документ) → статус (текст есть / текста нет / мало фото).
- Отдельным списком: блоки прототипа, для которых на старом сайте ничего нет (это вопросы к руководству).
- `inventory/redirects.csv`: старый URL (и якоря, где нужно) → новый URL. Новые slug'и предложи латиницей, утвердим позже.
- `content-model.md`: если есть `theme/` — выпиши из темы типы записей, таксономии и ACF-группы с именами полей. Если темы нет — предложи модель по прототипу. Отправная точка:
  - страницы: главная, лечение, СПА, проживание, семьям, мероприятия, территория, как добраться, контакты, вопросы-ответы, документы;
  - CPT `procedure` (процедуры и медуслуги, по шаблону «Грязелечение»), `program` (программы лечения), `accommodation` (корпуса, номера, коттеджи), `promo` (акции), `faq`, `doctor`, `document` (лицензии).
  Тему не создавай.
- Собери `handoff/`: content/old/*.md, _common.md, content-map.csv, facts.csv, redirects.csv, листы-превью, content-model.md, список вопросов → `handoff.zip`.
- **СТОП.** Дальше работа в чате.

### Этап 5. (в чате, не здесь) Переписывание и согласование
Claude в чате переписывает тексты под блоки, готовит документ, руководство комментирует, выходит утверждённая версия. Её экспорт в Markdown кладётся в `content/approved/`, формат будет описан при передаче.

### Этап 6. Импорт в WordPress
- `scripts/build_json.py`: content/approved + content-model.md + media/renamed → `content/json/`, ключ записи — slug. Валидация: обязательные поля заполнены, все файлы фото существуют.
- `importer/` — плагин с WP-CLI командой `wp kz import`:
  - создаёт или обновляет записи по slug (повторный запуск обновляет, не дублирует);
  - заполняет ACF через `update_field`;
  - загружает фото в медиатеку один раз (проверка по хэшу), ставит alt и миниатюры записей;
  - заполняет SEO-поля (плагин SEO уточню);
  - режим `--dry-run` с отчётом: что будет создано или изменено.
- Сначала тестовая установка. На боевую — только после моего «да» и бэкапа БД.
- Редиректы из redirects.csv — в формат, который выберем (CSV для плагина Redirection или правила nginx/.htaccess).

### Этап 7. Проверка
- Скриптом сравнить тексты на сайте с content/approved.
- Все фото на месте, alt не пустые, нет ссылок на старый домен.
- Все 301 из redirects.csv отвечают правильно (проверка curl).
- Отчёт в `inventory/qa-report.md`.
